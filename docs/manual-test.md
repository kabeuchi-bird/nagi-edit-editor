# 手動確認手順

自動テスト（`npm test`）では確認できない次の2点を手で確かめる。

- A. 出力を keymapper.conf に貼ると、入れ替え後の位置で機能が発動する（CLAUDE.md 10章）
- B. ブラウザ上で全機能が動く（`file://` と GitHub Pages の両方）

keymapper の挙動に関する記述の根拠は `docs/spec.md` 3章。

## A. keymapper での確認

### 前提

- Linux で keymapper（`keymapperd` サービスと `keymapper` クライアント）が動いている
- 中野藤右衛門氏の Linux版 v17 設定を使っていて、薙刀式で入力できる
- 確認用のテキストエディタ（gedit・Kate など）を開いておく

### 準備

1. 使っている設定ファイルのパスを変数に入れる。以降の手順はすべてこの変数を使う（同じシェルで続けて実行する）

   ```sh
   # 通常は次のどちらか。実際に使っている方を指定する
   CONF=~/.config/keymapper.conf
   # CONF=~/.config/keymapper/keymapper.conf
   ls -l "$CONF"
   ```

2. バックアップを取る

   ```sh
   cp "$CONF" "$CONF.bak"
   ```

### 貼り替え手順（各ケース共通）

1. ツールで配置を変え、「コピー」を押す
2. `$CONF` の `#固有名詞１` の行から `(C V Slash) >> ^ Control{Y}` の行までを選択し、コピーした内容で置き換えて保存する
3. 構文を検査する（エラーが出ないこと）

   ```sh
   keymapper --check -c "$CONF"
   ```

4. keymapper を再起動して設定を読み直す。参照元設定は `@options no-update` のため、保存しただけでは反映されない

   ```sh
   pkill -x keymapper; keymapper -c "$CONF" &
   ```

   自動起動の設定で起動している場合は、ログインし直してもよい（その場合、自動起動側が `$CONF` を読む設定になっていることを確認する）

### ケース

各ケースとも、テキストエディタ上で薙刀式をオンにした状態で同時押しする。

| # | ツールでの操作 | 確認内容 |
|---|---|---|
| A1 | 何も変えない（「すべて既定に戻す」） | 「既定との差分を表示」でハイライト行がない。貼り替え後、`D F J` で↑、`D F M` で↓、`C V H` でコピー、`J K R` で保存が動く（貼り替え前と同じ） |
| A2 | 右1面の J（↑）と M（↓）を入れ替える | 出力で `(D F J) >> ^ ArrowDown` と `(D F M) >> ^ ArrowUp` の2行だけが変わる。`D F J` でカーソルが下へ、`D F M` で上へ動く |
| A3 | 左1面の R（保存）と右2面の H（Copy）を入れ替える（面またぎ） | 文字を選択して `J K R` でコピーされ、`C V H` で保存が動く |
| A4 | 右1面の Y（ホーム）を空にする | 出力から `(D F Y)` の行が消える。`D F Y` で Home が発動しない |
| A5 | 右1面の Y を選び、詳細パネルで expr を `^ Control{Home}` に変える | 出力が `(D F Y) >> ^ Control{Home} # ホーム` になる。`D F Y` で文書の先頭へ移動する |
| A6 | 固有名詞面にテキスト挿入「テスト」を置く | 出力に `#(U I ?) >> ^ "テスト" # テスト（Linux未対応）` がコメントアウト行で出る。`keymapper --check` が通る |

### 後片付け・トラブル時

- 元に戻す：`cp "$CONF.bak" "$CONF"` のあと、手順4と同じく keymapper を再起動
- キー入力がおかしくなったら Shift+Escape+K で `keymapperd` を終了できる（README記載の緊急用の組み合わせ）

## B. ブラウザでの確認

Firefox と Chromium それぞれで、`dist/index.html` を `file://` で開いた場合と、公開URL（GitHub Pages）で開いた場合に確認する。

`file://` 用のビルド：

```sh
npm run build   # dist/index.html を作り、中身の検査まで行う
xdg-open dist/index.html
```

| # | 操作 | 期待結果 |
|---|---|---|
| B1 | スロットを別のスロットへドラッグ（同じ面・面またぎ） | 入れ替わり、両方に「既定から変更」の点が付き、出力が変わる |
| B2 | 左1面の E（予約）へドラッグ、クリック入れ替え | どちらも受け付けない |
| B3 | キーをクリック → 別のキーをクリック | 入れ替わる。Tab で移動して Enter/Space でも同じ |
| B4 | パレットの項目をキーへドラッグ／キーを選択してパレットの項目をクリック | そのキーが上書きされる |
| B5 | キーをパレットへドラッグ／キーを選択して Delete | キーが空になる |
| B6 | Ctrl+Z / Ctrl+Shift+Z | 直前の操作が戻る／やり直される（カスタムアクションの追加・削除、インポートも含む） |
| B7 | 詳細パネルで名前・expr を編集 | 出力に反映される。パレットに同じ名前のカスタムアクションが増え、既定カタログ側は変わらない |
| B8 | expr に `^ Shift{ArrowUP` と入力 | 括弧と不明なキー名の警告が出る |
| B9 | 面の「既定に戻す」、詳細パネルの「このキーを既定に戻す」、「すべて既定に戻す」 | それぞれの範囲が既定に戻る。カスタムアクションは残る |
| B10 | 出力オプションの3つのチェックボックスを切り替える | 出力が docs/spec.md 4章のとおり変わる |
| B11 | 「コピー」を押す | クリップボードにコピーされる。使えない環境では全選択と案内表示になる |
| B12 | 配置を変えてページを再読み込み | 配置・カスタムアクション・出力オプションが残る |
| B13 | エクスポート → 「すべて既定に戻す」 → インポート | エクスポート時の状態に戻る |
| B14 | 未知のアクションIDを含む JSON をインポート（エクスポートしたファイルを書き換える） | エラー一覧が表示され、そのスロットは空、残りは読み込まれる |
| B15 | Firefox の `about:config` で `dom.storage.enabled` を `false` にして開く（localStorage が使えない環境の再現。確認後は `true` に戻す）。※最近のブラウザはプライベートウィンドウでも localStorage が使えるため、その方法では再現しない | 「保存できません。JSONでエクスポートしてください」と表示され、操作は続けられる |
| B16 | 幅を狭くする（スマートフォン幅） | 面が1列になり、横スクロールが出ない |
